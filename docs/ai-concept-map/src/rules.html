1规则头 = 注入开关

alwaysApply: true 表示这条规则每次会话开始自动进入模型上下文，不用我在提问里重复交代。改这个文件，等于改 AI 在本项目里的默认行为。

2规则必须是可验收的约束

「必须用 tmp_path 临时库、两处 DB_PATH 都要 patch、pytest 全绿才交付」——每一条都能被测试验证。来自真实踩坑：默认参数绑定 DB_PATH 导致 monkeypatch 失效。

3落点 = 项目根，随 git 走

路径固定在 .trae/rules/project_rules.md，和代码一起提交，队友 clone 下来就生效。这就是"规则写在哪里"的答案：不写进对话，写进仓库。
